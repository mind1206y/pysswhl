# 旧系统数据迁移约定

新系统是全新开发,但以后照着旧系统开发业务模块时,旧库的历史数据要能导进来。为保证这件事顺畅,定以下几条约定。

## 背景

- 旧系统:SQL Server,三个库 `db_plan`(主库)、`ssjcxt`、`fapiaodb`
- 新系统:MySQL(本机 9.7.1),统一编码 `utf8mb4`
- 原则:**做一个模块,迁一个模块的表**,不做一次性全量迁移

## 约定

### 1. 表名、字段名尽量沿用旧库

在 MySQL 里重建某张业务表时,表名和字段名尽量与旧库一致(拼写不合理的可以改,但要在本文件登记映射关系)。这样导入脚本基本就是"导出→导入",不需要逐字段翻译。

### 2. 保留旧主键 ID,并调整自增起点

旧表主键多为 int 自增。导入时**保留旧 ID 不变**,导入完成后把新表自增起点调到旧数据最大 ID 之后,避免新写入的数据与导入数据冲突:

```sql
ALTER TABLE 表名 AUTO_INCREMENT = 旧最大ID + 1;
```

### 3. 导入脚本统一放 `backend/scripts/`

命名如 `import_vehicles.py`。推荐路径:SQL Server →(pymssql 直连或 SSMS/BCP 导出 CSV)→ pandas 简单清洗(可选)→ PyMySQL 写入 MySQL。

要求:**脚本可重复执行**(先清空目标表或按 ID 幂等),方便反复调试。

### 4. 字典/枚举值先核对再导

旧系统不少状态字段是数字或拼音缩写,导入前先 `SELECT DISTINCT` 看一遍取值,必要时在新表加映射。

### 5. 每迁一个模块,在下面登记一节

```
## 已迁移模块
### 车辆管理(2026-xx-xx)
- 源:db_plan.dbo.vehicles → 目标:sswhl_new.vehicles
- 字段变更:无
- 特殊处理:状态字段 1/2/3 → active/frozen/scrap
```

## 用户与密码

用户表是全新的(users),不从旧库导入;密码不迁移,由管理员在新系统重建账号。
