# 旧系统数据迁移约定

新系统是全新开发,但以后照着旧系统开发业务模块时,旧库的历史数据要能导进来。为保证这件事顺畅,定以下几条约定。

## 背景

- 旧系统:SQL Server,三个库 `db_plan`(主库)、`ssjcxt`、`fapiaodb`
- 新系统:MySQL(本机 9.7.1),统一编码 `utf8mb4`
- 原则:**做一个模块,迁一个模块的表**,不做一次性全量迁移

## 约定

### 1. 表名、字段名尽量沿用旧库

在 MySQL 里重建某张业务表时,表名和字段名尽量与旧库一致(拼写不合理的可以改,但要在本文件登记映射关系)。这样导入脚本基本就是"导出→导入",不需要逐字段翻译。

### 2. 保留旧主键 ID,并调整自增起点

旧表主键多为 int 自增。导入时**保留旧 ID 不变**,导入完成后把新表自增起点调到旧数据最大 ID 之后,避免新写入的数据与导入数据冲突:

```sql
ALTER TABLE 表名 AUTO_INCREMENT = 旧最大ID + 1;
```

### 3. 导入脚本统一放 `backend/scripts/`

命名如 `import_vehicles.py`。推荐路径:SQL Server →(pyodbc + "ODBC Driver 17 for SQL Server" 直连,中文原生 Unicode 无乱码)→ PyMySQL 写入 MySQL。

注意:**不要用 pymssql**——2.4.x 的 FreeTDS 对老版本 SQL Server(2008 时代)握手不稳定(时连时不连),且 varchar 需手动转 GBK;pyodbc + Driver 17 实测稳定。

要求:**脚本可重复执行**(先清空目标表或按 ID 幂等),方便反复调试。

### 4. 字典/枚举值先核对再导

旧系统不少状态字段是数字或拼音缩写,导入前先 `SELECT DISTINCT` 看一遍取值,必要时在新表加映射。

### 5. SQL Server `datetime` 写入 MySQL 前先截断到秒

旧库 `datetime` 精度是 1/300 秒(pyodbc 会读出 `.997` 这类微秒),而新库统一用 `DATETIME(0)`。直接写会被 MySQL **四舍五入进到下一秒**,导致登记日期/最后操作日期逐列比对差 1 秒(`cl_feiyong` 34 行里踩到 35 处)。导入脚本统一 `value.replace(microsecond=0)` 后再写,逐列比对才能 0 差异。
