# 2026-11-15 首次容器部署踩坑:1045 Access denied

## 现象
服务器执行 `install-container.sh --dump` 到最后一步 `init_db` 失败:
`pymysql.err.OperationalError: (1045, "Access denied for user 'sswhl_app'@'172.17.0.3'")`。
前置步骤全部成功(网络/卷/容器/建库/导入数据都过了)。

## 根因(重要,以后所有 shell 读 .env 都会踩)
`backend/.env` 是 **Windows CRLF**(实测 raw 里 CRLF=True,12 个 \r)。
- Linux 上 `grep | cut -d= -f2-` 取 DB_PASSWORD 会把尾部的 `\r` 一起带出来(Windows 的 Git Bash grep 会剥离 CR,**Linux 不会**,所以本地测不出来);
- 脚本用这个"带回车"的密码 `CREATE/ALTER USER`;
- 容器内 Python(pydantic/dotenv)正确按 CRLF 解析,拿到干净密码;
- 两边差一个 `\r` → 1045。报错里的 `using password: YES` + `caching_sha2_password_auth` 是 MySQL 8 默认插件,不是插件问题。

## 修复(已进脚本)
1. `get_env()` 尾部加 `| tr -d '\r'`(根本修复);
2. 新增 `normalize_env()`,step 2 开头把 `backend/.env`、`deploy/.env` 的 CRLF 转 LF(sed -i 's/\r$//'),幂等;
3. 建号从 `SKIP_DB` 里拆出,**只要 sswhl-mysql 在跑就执行**(幂等 ALTER USER),并且建完立刻用应用账号回连 `select 1` 自检,失败当场 die,不再等到 init_db 才报;
4. 新增 `--only-account`(跳过数据导入,只修账号 + 跑 init_db + 起服务),用于本次补救。

## 交付
- `sswhl-fix-account.tar.gz`(5002 字节,只含 install-container.sh)给用户免重传 50MB;
- 整包重打 50MB;README 第七节排错表加 1045 那一行。

## 待观察
用户尚未回报修复结果。若 `--only-account` 后仍 1045,下一步查:密码是否含特殊字符、MySQL 里是否存在 `'sswhl_app'@'localhost'` 的更具体记录覆盖 `%`。

# 2026-11-15 续二:docker load 报 "too many non-empty layers in History section"

## 现象
服务器 `sudo docker load -i ~/sswhl-api-image.tar`,加载到最后一层(28.98MB)后报
`too many non-empty layers in History section`。**load 整体失败,镜像没换**,
接着 `up -d --force-recreate api` 起的还是旧镜像,`curl /api/health` 得到
`Recv failure: Connection reset by peer`(容器启动即崩,还是缺 exceptiongroup 那个错)。

## 根因
`rebuild_image_local.py` 复用旧 tar 的前 4 层时**只截断了 `rootfs.diff_ids`**(取 `[:n_base]`),
**没有截断 `history`**,又 append 了一条新层记录 → history 非空 6 条 vs 层数 5 条。
Docker 在 `load` 收尾按 `非空 history 数 == 层数` 校验,超了直接拒收整包。

## 修复
1. 新增 `build/fix_image_tar.py`:对已打好的 tar 做"JSON 手术"——只重写
   manifest.json / config / repositories 三个小文件,层字节原样搬运;
   按非空计数截到 n_base 后补一条新层记录,再逐层 sha256 对 diff_ids 自检。
2. `rebuild_image_local.py` 补 history 截断逻辑(第 3 步改写 config 处),根因修复。
3. 顺带去掉 `IMG_TAGS` 里的 `python:3.10-slim`:load 到目标机会把服务器同名 tag
   顶到我们的镜像上(污染别人基于该 tag 的构建)。现在只留 `sswhl-api:1.0`。
4. 新包 74055680 bytes / MD5 `5f936b5e9a24aa2f521895ed3ba134b1`,坏包留档
   `sswhl-api-image.bad.tar`。

## 教训
手工组装 docker save 包时,**`history` 非空条目数必须严格等于 `Layers` 数 == `rootfs.diff_ids` 数**,
三者是 Docker 的硬校验;empty_layer 条目数量不限,可随意插在中间。
自检脚本必须断言这三者相等,不能只断言 diff_ids 与层数。
