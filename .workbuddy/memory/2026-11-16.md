# 2026-11-16 登录失败:非安全上下文导致 crypto.subtle 缺失

## 现象
内网浏览器打开 `http://172.16.43.126:18080` 登录报：
`TypeError: Cannot read properties of undefined (reading 'importKey')`
at `auth.js` 的 `encryptPassword`。页面本身能开,一点登录就崩。

## 根因
**Web Crypto API 只在「安全上下文」(Secure Context) 暴露**:
`https://` 任意、`http://localhost`、`http://127.0.0.1`。
内网用 `http://<内网IP>:18080` 访问属**非安全上下文**,`window.crypto.subtle` 是 `undefined`,
`crypto.subtle.importKey` 直接 TypeError。

**为什么开发时一直没发现**:开发走 `http://localhost:5173`,localhost 算安全上下文,
`crypto.subtle` 存在,加密路径正常。只有换成内网 IP 的纯 HTTP 才暴露 ——
典型的"本地环境掩盖部署问题"。

## 修复(降级 + 兼容,不动加密协议本身)
1. `backend/app/core/security.py`:新增 `PLAIN_PASSWORD_PREFIX = "plain:"`,
   `decrypt_password()` 见前缀直接返回剩余部分,否则走原 RSA-OAEP 解密。
   两处调用(login / change_password)的 `except (ValueError, TypeError)` 无需改
   (实测 `binascii.Error` 与 `ValueError` 都是 ValueError 子类,能被捕获)。
2. `frontend/src/api/auth.js`:新增 `hasWebCrypto()`,`crypto.subtle` 不可用时
   返回 `'plain:' + password`;可用时仍走 RSA 加密。以后一旦套上 HTTPS 自动恢复加密,不用再改。
3. 重新 `npm run build`,产物 `index-Bz4ZwqFI.js`(旧的是 `index-D43kdeiQ.js`)。

## 交付
`sswhl-fix-login.tar.gz` 5.7MB / md5 `fda36de03107ba004f18dd8635a1e0d0`
含 `backend/app`、`backend/scripts`、`frontend/dist`(正好是 update.sh --pkg 要求的三个目录)。
**不需要重建镜像**:这三样都是只读挂载进容器的,覆盖宿主文件 + 重启即可。
部署:`sudo bash /opt/sswhl/deploy/update.sh --pkg ~/sswhl-fix-login.tar.gz`,
完事必须 Ctrl+F5 强刷(index.html 缓存会继续引用旧 js 文件名)。

## 安全取舍(记下来,别再纠结)
RSA 加密在纯 HTTP 下本来也防不住中间人(公钥可被替换),它的实际价值是
"密码不以明文出现在抓包/开发者工具/日志里"。降级后内网抓包能看到密码,
风险可接受;真要解决得给服务上 HTTPS(自签证书要每台客户端装根证书,更麻烦)。

## 临时应急办法(不传文件时)
Chrome/Edge 打开 `chrome://flags/#unsafely-treat-insecure-origin-as-secure`,
填 `http://172.16.43.126:18080` 设为 Enabled 后重启浏览器,
该 origin 会被当安全上下文,`crypto.subtle` 恢复,走原加密路径。
**只适合个人临时验证,不能当方案**(每台客户端都得设)。

## 收藏夹 /login 导致无法自动进系统（2026-11-16）
- 现象：本地能自动进、服务器不能。真因不是缓存也不是后端：用户收藏夹存的是 `http://<ip>:18080/login`，而守卫对 `/login` 是**直接放行**（`if (to.path === '/login') return true`），有有效 token 也停在登录框。localStorage 按 origin 隔离这点只是让“本地能进”看起来正常（本地存过 token）。
- 修：守卫 `/login` 分支改为——无 token 直接放行；有 token 先 `await auth.loadUser()`，通过则回 `readLastRoute() || '/dashboard'`（且显式排除 `'/login'` 防自循环），失败则 `auth.logout()` 留在登录页。⚠️ 不要在登录页无条件跳 last-route 而不验证 token：拦截器会在 401 时 push('/login')，会与守卫返回打架、多一次无谓导航。
- 顺带根治缓存：`main.py` 在 SERVE_FRONTEND 块内加 http 中间件——`/assets/*` → `public, max-age=31536000, immutable`（文件名带 hash）；其余非 `/api` 且 content-type 为 text/html → `no-store, must-revalidate`。此前 FileResponse 无任何 Cache-Control，浏览器启发式缓存旧 index.html → 指向已删除的旧 hash JS → 白屏，README 里到处教用户 Ctrl+F5 就是这个。TestClient 实测：`/`、`/login` = no-store，`/assets/index-*.js` = immutable。
- 新精简包 `sswhl-update.tar.gz` md5 `f5e446c2159ac6af54c56eb66af58bf6`（1.7MB），dist JS 改名 `index-DxGnu_e1.js`。
