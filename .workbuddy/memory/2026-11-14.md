## 内网部署推进（172.56.43.126）

**接入限制确认**：本机 aTrust 连的是另一个办公 VPN，且为应用级代理（只代理浏览器进程）。实测
`172.16.43.126:22/443`、`172.56.43.126:22`、`172.56.11.11:22/443/80` 从开发机全部不通，
WinSCP / Xftp / Xshell / scp 均不可用；堡垒机「运行下载」也没有 WinSCP（给了 463 字节的 .xfp 会话文件）。
最终只能走**堡垒机网页终端 + 其自带文件传输**。已把全部环境探测结果整理成 `docs/服务器环境记录.md`。

**手工组装 Docker 镜像**（开发机无 Docker、WSL 被安全策略禁用，无法 build）：
`deploy/tools/build_image_offline.py` 实现「无 daemon 造镜像」——
1) 从 `docker.1panel.live`（Hub 直连 000 不通）拉 base manifest，按 digest 下载 `python:3.10-slim`
的 4 个层并逐层 sha256 校验；2) `pip install --target` + `--platform manylinux2014_x86_64
--python-version 3.10 --abi cp310 --only-binary=:all: --no-index` 把 37 个离线 wheel 装进
`usr/local/lib/python3.10/site-packages`（78 个包目录，含 bin/ 与 dist-info）；3) 复制 backend（排除
`.env`/`rsa_key.pem`/`.venv`/uploads）与 `frontend/dist`；4) 打第 5 层、算 diffID、改写 config 的
`rootfs.diff_ids`/`Env`/`Cmd`/`WorkingDir`/`ExposedPorts`，补一条 history；5) 拼 `manifest.json` +
`repositories` + config json + `<layer>/layer.tar` 成 `docker load` 格式。
产物 `sswhl-api-image.tar` 70.6MB，tag `sswhl-api:1.0` + `python:3.10-slim`，自检 5 层 sha256 全对。

**compose 调整**：`api` 服务挂 `profiles: ["docker-api"]`（默认 `up -d` 仍只起 mysql）；容器内必须
覆盖 `DB_HOST=mysql`、`UPLOAD_DIR=/app/backend/uploads`、`FRONTEND_DIST=/app/frontend/dist`
——否则 `.env` 里的宿主机路径/127.0.0.1 会让容器连不上库、附件写到不存在目录。

**踩坑记录**：`.dockerignore` 一开始把 `deploy/wheels` 排除了，但 Dockerfile 要 COPY 它；已改。
`.env`/`rsa_key.pem` 一律运行时只读挂载，不打进镜像层（层能被 `docker save` 导出）。
