# 2026-11-13 内网部署方案落地（pysswhl → 172.56.43.126）

## 目标机勘察结论（堡垒机 DAS-USM / 网页 SSH）
- Ubuntu 22.04.2 LTS，8 核 / 16G / 490G（剩 308G），用户 `sysmgr`（sudo 组、**免密**），Python **3.10.6** + venv 可用。
- 机器跑的是 **Docker**（不是 LXD）：`xinkong` 栈占 8000/8001/7004/5150/18086；`xinkong-mysql` 映射 7004→3306，**宿主 3306 无监听**。
- 本机镜像齐全：`mysql:8`(564M)、`mariadb:10`、`postgres:14`、`redis:7`、`nginx-proxy-manager`、`openresty` 等 —— **但没有 python 基础镜像**。
- 网络：apt 索引可用（nginx 模拟安装通过）；**pypi 不通（000）**；开机报 changelogs 连接失败 → 全离线部署。

## 采用的方案（不用 nginx）
宿主 Python venv 跑 API + Docker `mysql:8` 容器 + **FastAPI 直接托管前端 dist**，对外只开 18080。
- 容器 `sswhl-mysql`：独立网络 `sswhl_net`、独立卷 `sswhl_mysql_data`、端口 `127.0.0.1:13306:3306`。
- 服务 `sswhl-api`：systemd，`/opt/sswhl/backend/.venv/bin/uvicorn ... --port 18080`，单 worker。

## 三个必须记住的坑
1. **lower_case_table_names**：开发机 MySQL 9.7.1 且 lctn=1，表名实存小写；但 11 个 `__tablename__` 带大写（CLdui/LeakFile/celouTb/cl_cxTP/OilCard/PlusOil…）。Linux 默认 lctn=0 → 找不到表，且 create_all 会**另建同名空表**造成“有表无数据”。容器必须加 `--lower-case-table-names=1`（首次初始化前生效，之后改会启动失败）。
2. **PASSWORD_PEPPER 必须沿用开发机**：dump 里的哈希含旧 pepper，换新 pepper = 全体用户登录不了。install.sh 检测到已有 .env 时保留，只校准 DB_* 与 SERVE_FRONTEND/ENABLE_DOCS。
3. **UPLOAD_DIR 不能留空**：代码是 `Path(settings.UPLOAD_DIR).resolve()`，空值等于 cwd（backend/），附件会散落。模板写死 `/opt/sswhl/backend/uploads`。

## 代码改动
- `app/core/config.py` 新增 `SERVE_FRONTEND: bool=False`、`FRONTEND_DIST: str=""`。
- `app/main.py` 末尾（所有 include_router 之后）加托管：`/assets` 静态挂载 + `/{full_path:path}` SPA 回退；`api/`、`docs`、`openapi.json` 直接 404；`resolve()+startswith` 防路径穿越；dist 缺失时启动即报错。开发环境默认 false 不受影响。
- 本地实测：`/` 与 `/overtime/apply` → 200 HTML；`/assets/*.css` 200；`/api/health` 200 JSON；`/api/nope`、`/docs` → 404 JSON。
